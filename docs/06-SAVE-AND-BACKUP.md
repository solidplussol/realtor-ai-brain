# 06 — SAVE AND BACK UP

When Claude creates or updates notes, those file changes need to be saved.

GitHub Desktop makes this beginner-friendly.

## The exact save flow

1. Open **GitHub Desktop**
2. Go to the **Changes** tab (the list of files that changed)
3. Review the changed files
4. Write a short description in **Summary** (the box where you briefly describe this save)
5. Click **Commit to [branch name]** (**commit** means save this version on your computer; **branch** means the current line of work for this project)
6. Click **Push origin** (**origin** means the GitHub copy connected to this project)

- https://docs.github.com/en/desktop/making-changes-in-a-branch/pushing-changes-to-github-from-github-desktop

## What those words mean

- **Commit** = save a version or checkpoint locally on your computer
- **Push** = send those committed changes to GitHub

That means:

- commit first
- push second

If you only commit, the saved version is still only on your computer.
If you push, the committed version is also sent to GitHub.

## Good beginner habit

After a setup session, a meaningful update, or a batch of new notes:

1. review the changes
2. commit them
3. push them

That gives you both a local checkpoint and an online copy.
